# Portfolio audit — July 2026

Living record of the audit that followed the Next 16 / Tailwind 4 / Prisma 7
upgrade round. Part 1 is what the first pass changed and how it was verified;
part 2 is what is still open, ordered into the passes that come next.

Original findings are in the git history of this file (first written at
`73eda18`, before any of it was fixed).

**Current health:** `pnpm lint`, `pnpm typecheck`, `pnpm build`, and
`pnpm prettier --check src` all pass. 18 routes, all Static or SSG.
`pnpm audit` reports 7 advisories, none of them reachable from shipped code.

# Part 1 — What the first pass changed

15 commits on `fix/audit-first-pass`, 37 files, +1195 / −157.

## 1.1 Vulnerabilities: 34 → 7

| Step | Change                           | Left  |
| ---- | -------------------------------- | ----- |
| 0    | baseline                         | 34    |
| 1    | `pnpm update` — lockfile refresh | 16    |
| 2    | `next` `16.2.10` → `16.2.12`     | **7** |

Step 1 cleared 18 advisories with no upgrade decision to make: the patched
versions were already inside their parents' semver ranges and the lockfile had
simply never re-resolved them — `js-yaml` 3.14.1→3.15.0 (3 advisories),
`minimatch` 3.1.2→3.1.5 (3), `picomatch` (2), `flatted` (2), `brace-expansion`
(2), `@babel/core` + `@babel/helpers` (2), `yaml`, `mdast-util-to-hast`,
`fast-uri`.

One deviation from the plan as written: this version of pnpm also lifted the
manifest ranges for direct dependencies with newer in-range releases (React
19.2.8, react-hook-form 7.83, resend 6.18, eslint-config-next 16.2.12, the Radix
packages). The audit had predicted "no manifest change". All were patch or minor
and all were on the "worth taking alongside" list anyway, so they were kept.

Step 2 removed all nine Next advisories, four of them high: middleware/proxy
bypass, two SSRFs, and a Server Actions DoS. Most do not apply to a static site
with no middleware or rewrites, but three touch Server Actions and this site
ships two.

**The optional third step was not taken.** Overriding `postcss` and `sharp`
would have gone 7 → 3. It is deliberately deferred — see §2.1.

Two notes on how 2.5 and 2.9 were resolved, since both differ slightly from the
original recommendation:

- **The contact rate limiter is in-memory, not Postgres.** The audit suggested a
  `contact_submissions` table. That needs a schema change and a `prisma db push`
  against the live Neon database, which is a deploy step rather than a code
  change. The in-memory limiter stops the realistic case — one source in a loop
  — and is documented in the module as a speed bump rather than a guarantee. A
  durable limit is listed in §2.4 below.
- **The Resend sender was made configurable, not changed.** `CONTACT_FROM_EMAIL`
  and `CONTACT_TO_EMAIL` now drive the addresses, defaulting to the current
  values. Actually moving off `onboarding@resend.dev` requires verifying a
  domain in Resend, which only the account owner can do — see §2.2.

## 1.3 SEO added

## 1.4 One thing that was not a fix

The last commit reformats nine files. Six were never touched by this work — the
dependency refresh moved `prettier-plugin-tailwindcss`, and its new class
ordering disagrees with how those files were last formatted. Verified

set of class tokens is byte-identical before and after, and class attribute

`CLAUDE.md` and `package.json` are still Prettier-dirty. Both already were
before this branch, so they were left alone.

# Part 2 — What is still open

## 2.1 The 7 remaining advisories

None are reachable from shipped code. Grouped by what it would take to close
them:

**Needs a `pnpm.overrides` entry (4).** `next` pins `postcss` to an exact
`8.4.31` and caps `sharp` at `^0.34.5`, so neither moves on its own.

```json
"pnpm": {
  "overrides": { "postcss": "^8.5.23", "sharp": "^0.35.3" }
}
```

This was tested during the audit — it installs, builds, and produces an
identical route table, taking the count to 3. It is deferred because all four
are build-time only: the postcss issues (source-map path traversal, arbitrary
file read, `</style>` XSS in the stringifier) affect Next's internal CSS
pipeline running over your own CSS, and Vercel handles image optimization
without the bundled `sharp`. Carrying an override means owning a pin that Next
will eventually move past on its own.

Take it if a clean `pnpm audit` matters more than the pin. If not, this section
is the record of the decision. The `sharp` bump crosses a libvips major, so
check a project thumbnail if you do.

**Resolves itself (2).** `find-my-way` and `valibot` are pinned inside
`@prisma/dev`, which the current `prisma@7.9.0` has not picked up yet. Dev-only
CLI code; neither ships.

**False positive (1).** `brace-expansion` resolves to `1.1.16`, which _is_ the
patched 1.x. The advisory declares its vulnerable range as `<=5.0.7`, which
semver-matches `1.1.16` across majors. Nothing to do.

`AppProviders` currently wraps every page in two context providers that nothing
consumes. Removing them leaves it a thin wrapper around `ThemeProvider`, at
which point it can be inlined into `layout.tsx`.

**Three dependencies go with it:** `@radix-ui/react-dropdown-menu` (only the
dead dropdown), `react-intersection-observer` (only the dead hook), and
`framer-motion` — 5.6 MB whose one live use is a single opacity fade on the
contact page, replaceable with CSS. Dropping it also makes `contact.tsx` a
server component.

**Unused exports.** `getErrorMessage` in `src/lib/utils.ts` has no call sites.
`validateString` is also uncalled but now redundant — the contact schema does
its job properly; delete it too. `FormDescription` in `ui/form.tsx` is still
unused (`FormMessage` is now wired up).

**Commented-out code** in `animated-link.tsx` (an alternative underline
treatment wrapped around the live `{children}`) and `data/links.ts`.

**Typos**, all still present: "seletion" in the portfolio page summary, "The
sender&apos; email" in the contact email template, "Develeoper"/"Enginner" in
`data/experience.ts`, and "action-advuenture"/"Grubble Grub" in
`grapple-grub.mdx`.

## 2.4 Third pass — structure

**Validate frontmatter with Zod instead of casting it.** Every reader still does
`...(data as Omit<PostMetadata, 'slug'>)`, which is a promise to the compiler
rather than a check. This pass found two bugs that a parse boundary would have
caught for free — the `link` type that did not match the content, and the
unpadded dates. `parseContentDate` now throws on a malformed date, which is a
start, but the rest of the frontmatter is still unchecked. A
`PostFrontmatterSchema` / `ProjectFrontmatterSchema` would fail the build with a
filename and a field name.

**Wrap the content readers in React's `cache()`.** Rendering one post still
costs four filesystem reads, because `generateMetadata` and the page component
each call `getPostData` independently. The duplicated read loop in
`getFeaturedProjects` is gone, but the per-request duplication is not.

**Make `TechStackIcon` a lookup map.** Still a 328-line switch over a 45-member
union reached by an unchecked `tech as TechStackIconName` cast, so a typo in
`techStack:` silently falls through. Pairs with the Zod work: make the
frontmatter the checked boundary and the switch collapses.

**A durable contact rate limit.** The in-memory one does not survive across
serverless instances. Either a `contact_submissions` table following the
`post_view_sessions` pattern, or a platform-level rule at the Vercel edge.

**Add CI.** A GitHub Action running `pnpm lint && pnpm typecheck && pnpm build`.
All three pass today; CI is what keeps that true. Add Dependabot or Renovate on
the lockfile while you are there — a third of the original alert count was pure
lock drift.

**Two tests worth writing** (there are none, and that is fine for a personal
site, but these two encode real logic and both have already had bugs):
`getReadingTime`, and the date parsing/sorting path with an explicit non-UTC
timezone.

**Security headers.** `next.config.mjs` still sets none. `Strict-Transport-Security`,
`X-Content-Type-Options`, `Referrer-Policy`, `X-Frame-Options`, and
`poweredByHeader: false` are a small block with no downside.

**Decide on the Prisma leftovers.** `User`, `Account`, and `GuestbookNote` are
still in the schema purely so `db push` does not drop them. Either build the
guestbook (§2.5) or drop the tables in a migration.

## 2.5 Features

Now that per-page metadata exists, the SEO work has an obvious next step and the
content work is mostly about surfacing things that are already written.

**Highest content-per-effort, because the content already exists:**

- **The experience timeline.** `src/data/experience.ts` holds four fully written
  entries — Epistemitek, Berkley Technology Services, Drexel, Dynasty11 — with
  dates, locations, descriptions, and icons, and has zero importers. It needs a
  component, not writing. (Listed as deletable in §2.3 _only_ if you decide
  against this.)
- **Post topics.** `PostMetadata.topics` is populated in both posts and rendered
  nowhere. Topic chips, then `/blog/topics/[topic]` pages, which also feed the
  sitemap.
- **`featured` on posts.** Declared in post frontmatter, used only by projects.
  Pin a post on the home page.

**SEO, continuing from §1.3:**

- **Dynamic OG images** via `opengraph-image.tsx` in each `[slug]` segment —
  title, date, reading time through `ImageResponse`. The metadata plumbing is
  now in place, so this is the remaining visual half.
- **JSON-LD** `BlogPosting` / `Person` structured data.
- **RSS feed** at `feed.xml/route.ts` from `getSortedPosts()`. ~30 lines, and a
  blog without one is not followable.

**Reading experience:**

- Table of contents — `rehype-slug` and `rehype-autolink-headings` already emit
  the heading IDs, and `BackButton` already occupies the left gutter at
  `lg:-left-48`.
- Reading progress bar — the same primitive `CLAUDE.md` recommends in place of a
  loading screen.
- Prev/next post links; `getSortedPosts()` already returns the ordered array.
- Blog search — `Search` and `HighlightedText` exist and now handle
  metacharacters safely.

**Other:**

- `@vercel/speed-insights` is not installed; one import in `layout.tsx` gives
  real-user Core Web Vitals, which would confirm the §2.7 image work.
- Fold `craft.ryangan.me` into the site as a `/craft` route.
- A uses/now page.
- Refresh the home page copy — it still says "3 years of experience" and
